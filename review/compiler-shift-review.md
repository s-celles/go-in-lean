# Adversarial review: generated shift-lowering theorems (`ARM64Shifts.lean`, `AMD64Shifts.lean`) vs go1.25.5

Claim under attack: the 96 + 96 theorems generated by `scripts/arm64_shift_rules.py`
and `scripts/amd64_shift_rules.py` establish the soundness of the Go 1.25.5
generic-shift lowering rules `ARM64.rules:148-200` and `AMD64.rules:194-224`
(`$(go env GOROOT)` = `/opt/homebrew/Cellar/go/1.25.5/libexec`, `go version go1.25.5 darwin/arm64`).

Read in full: `GoInLean/Compiler/ARM64.lean`, `AMD64.lean`, both translators, samples of
both generated files, the two rule blocks, `rulegen.go` (`expandOr`,
`excludeFromExpansion`), `genericOps.go` (shift ops), `rewrite.go` (`shiftIsBounded`,
`zeroUpper{32,48,56}Bits`), `prove.go` (where `AuxInt = 1` is set), `ssagen/ssa.go`
(OLSH/ORSH lowering), `ssagen/intrinsics.go` and `memcombine.go` (other producers of
shift ops), `AMD64Ops.go`/`ARM64Ops.go`, `amd64/ssa.go` (SBB codegen), the
`*latelower.rules` files. Nothing outside `review/` was modified. Scratch work:
`/private/tmp/claude-501/-Users-scelles-git-github-s-celles-go-in-lean/52e023c5-3f5b-40fc-a231-6f1814ca27c7/scratchpad/review2/`
(`Related.lean`, `Mut.lean`, `gotest/`).

## Verdict

**Not falsified.** I found no model mismatch that invalidates a theorem, no skipped rule
instance, and no counterexample rule; the differential tests found no compiler
miscompilation. Confidence that the 192 theorems are *faithful statements of what they
claim*: high (~90%). Confidence that they *establish soundness of the lowering* is
lower (~75%), because the claim depends on three things the theorems do not cover (see
"Problems / caveats", most important first).

## Problems / caveats (none is a bug in go1.25.5)

1. **Low-bits-only conclusion vs. a compiler that also relies on high bits (AMD64).**
   Every theorem concludes `(lowered).setWidth W = Go result`. But
   `AMD64latelower.rules:11` `(MOVLQZX x) && zeroUpper32Bits(x,3) => x` relies on
   `SHLL/SHRL/SARL/ANDL` (the lowered forms of the 32-bit shifts) having **zero upper
   32 bits**. That stronger fact is not proved by the generated files. It does hold in
   the model: I proved `lsh32_unbounded_upper` (full 64-bit equality of the
   `ANDL(SHLL, SBBLcarrymask(CMPQconst [32]))` sequence with `zext(x <<< y)`) and
   `rsh32u_bounded_upper` in `Related.lean`. Recommend generating the full-register
   statement for every `W = 32` unsigned instance on AMD64. (`zeroUpper48/56Bits` do
   not list `SHRW/SHRB/ANDL`, which is correct: the model's `put 16/8` shows their upper
   bits are *not* zero; signed sub-64 types are excluded by the issue-68227 guard.)
2. **The op-width premise (`AxB`: shifted value has A bits) is violated by one
   producer.** `ssagen/intrinsics.go:1343` (`internal/runtime/maps.bitsetRemoveBelow`,
   AMD64 only) builds `Lsh8x8 <uint64> (Const64 1) i` with a **64-bit** shifted value
   and a **uintptr** count. The theorems (which take the value as 8-bit and the count
   as 8-bit) say nothing about it, and `prove.go` would compute `bits = 64` from
   `Args[0].Type.Size()` while the AMD64 lowering uses `CMPBconst i [32]`. Outside
   `i < 8` the result is not "clear the lower i bits" (e.g. `32 <= i < 64` gives 0; `i =
   256` sees count 0). Unreachable: the only caller (`table.go:1020`) passes a slot index
   `< 8`. Not a bug, but it is a hole in the "model = all uses" argument.
3. **`shiftIsBounded` hypothesis is relative to `Args[0]`'s *type*, not the op name.**
   `prove.go:2350-2357`: bounded iff `lim.umax < bits || (lim.max < bits &&
   nonneg(by))`, `bits = 8*v.Args[0].Type.Size()`. For every producer except item 2
   these coincide, so `hb : y < W` (unsigned, at the count's width A) is the right
   rendering. Other AuxInt sources: Wasm/dec64 rules copy `[c]` only between ops of the
   same shifted width (not 64-bit lowering targets); `ssagen` never sets it; `reset`
   clears it; CSE keys on AuxInt. OK.
4. **Translator latent silent-skip**: `if name in names: continue` would silently drop a
   second rule for the same `(op, bounded)` pair. Today 96 instances map to 96 distinct
   names per file (counted independently), so nothing is dropped; any other unparsed
   shape raises `SystemExit` (not silent). Suggest turning the dedupe into an error.
5. **Trust base**: `#print axioms` on these `bv_decide` proofs shows
   `..._native.bv_decide.ax_*` (LRAT checked via `ofReduceBool`), i.e. the compiler
   of Lean is trusted, not only the kernel. Worth stating next to "proved".
6. **Robustness note (not a problem)**: no generated theorem depends on the "5-bit count
   for 8/16-bit x86 shifts" fact; with a 4-bit mask they still hold (the CMP bounds are
   16/8). That fact *is* load-bearing for neighbouring rules (`AMD64.rules:792-800`),
   which I checked separately.
7. **Latent (unreachable) condition**: `AMD64.rules:1197`
   `(CMPLconst (SHRLconst _ [c]) [n]) && ... c <= 32 ...` is false for `c = 32` under the
   hardware's 5-bit masking (`SHRL $32 == SHRL $0`; mutant `m5` refuted with
   `x = 2^64-1`). All `SHRLconst` producers in 1.25.5 emit `c&31` (`AMD64.rules:791`),
   so unreachable.

## Concrete binary tests — `gotest/`

`gen.py` → `main.go`: 96 `//go:noinline` functions = {8,16,32,64}-bit value ×
{8,16,32,64}-bit count × {`<<`, unsigned `>>`, signed `>>`} × {unbounded, bounded by
`if y < W`}. Value and count are truncations of 64-bit arguments (garbage high register
bits). Oracle: shift-free doubling/halving loops. 12 x-values × 1,809 counts (0..299
with 6 different high-bit patterns, plus 2^16, 2^32, 2^63, all-ones, …) = 21,708 cases
per function.

| Build | Result |
|---|---|
| darwin/arm64, default | 0 mismatches |
| darwin/arm64, `-N -l` | 0 mismatches |
| GOARCH=amd64 (Rosetta 2), default | 0 mismatches |
| GOARCH=amd64, `-N -l` | 0 mismatches |
| GOARCH=amd64 GOAMD64=v3 | not runnable under Rosetta |

`-d=ssa/prove/debug=1` reports "Proved … bounded" for all 48 bounded functions, so both
rule families are exercised. Disassembly matches the model, e.g. amd64 `rsh8x16u`:
`CMPW BX,$8; SBBL CX,CX; NOTL CX; ORL BX,CX; SARB CL,AL` (objdump prints the `D2 /7`
byte form as `SARL CL, AL`); arm64 `lsh64x8u`: `LSL R1,R0,R2; UBFX $0,R1,$8,R1; CMP
$64,R1; CSEL LO,R2,ZR,R0`.

## Suggested follow-ups

1. Generate full-register theorems for AMD64 32-bit unsigned lowerings (caveat 1).
2. Make the translators fail on duplicate names instead of `continue` (caveat 4).
3. Note in `docs/` that the theorems assume op width = type width of `Args[0]`, and
   that `bitsetRemoveBelow` is a known exception guarded by a caller invariant (caveat 2).
4. Add `Related.lean`'s count-simplification rules (`AMD64.rules:802-821`,
   `ARM64.rules:1013-1018`) to the generated set; they share the masking facts.
